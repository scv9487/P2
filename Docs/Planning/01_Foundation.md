# P2 기반 테스트 씬

이 문서는 초기 기반 구축 작업의 범위를 다룬다. 게임 전체의 방향과 앞으로의 기획 기준은 [핵심 기획 방향](00_GameDirection.md)을 따른다.

## 사용자 명시 요구

- IZ와 같은 방식으로 DS에 있는 기반을 참고하여 P2 신규 프로젝트를 설정한다.
- 게임 콘텐츠는 필요하지 않다.
- Play 가능한 테스트 씬에서 기본 입력, UI, 데이터 처리, 저장, 불러오기를 확인할 수 있어야 한다.

## 구현 시 보완한 사양

- 단일 `2_Test` 씬을 첫 빌드 씬으로 사용한다. 시작 시 초기 상태이며 자동 불러오기는 하지 않는다.
- 숫자 증감과 문자열 적용을 데이터 변경 예제로 사용한다. 초기값은 숫자 0, 문자열 `P2`다.
- 숫자 증감 단위 1, 범위 -999999~999999, 문자열 최대 32자는 CSV에서 읽는다. 문자열 앞뒤 공백을 제거하고 빈 값은 거절한다. 설정은 다음 Play부터 반영한다.
- 처리 횟수는 성공한 숫자/문자 변경만 센다. 같은 이름을 다시 적용하는 것은 변경으로 세지 않는다. 횟수 한도에서는 부분 변경 없이 거절한다.
- F1/F2는 숫자 증가/감소, F5/F9는 저장/불러오기, Escape는 안내 팝업 열기/닫기다. 텍스트 편집 중에는 단축키를 실행하지 않는다.
- 입력은 수집 순서대로 처리한다. 같은 프레임에 여러 번 요청해도 각각 처리하며, UI 입력 뒤에 해당 프레임의 키 입력을 수집한다.
- 팝업이 열리면 닫기 이외의 요청을 처리하지 않는다. 포커스를 잃으면 미처리 입력을 비운다.
- 초기화는 현재 메모리 상태만 초기화한다. 저장 파일은 유지하여 저장 → 변경/초기화 → 불러오기 비교가 가능하다.
- 저장 슬롯 하나를 `Application.persistentDataPath/P2Foundation/save.json`에 사용한다. 숫자, 문자열, 성공한 데이터 변경 요청 수만 저장하며 팝업/안내 문구/편집 중 초안은 저장하지 않는다.
- 형식 `P2.Foundation`, 버전 1. 임시 파일 기록 및 검증 후 교체한다. 불러오기 실패는 상태를 유지하고 화면에 이유를 표시한다. 자동 저장, 구버전 변환, 클라우드 저장은 포함하지 않는다.

## 설계 카드

| 항목 | 결정 |
| --- | --- |
| 입력 | uGUI 버튼/입력 필드와 키보드 → InputStream → InputBinding |
| 실행 | MainFlow.Update의 EventQueue 단계 → FoundationEventHandler |
| 원본 상태 | FoundationDataContainer. View는 Reader로 받은 값만 표시 |
| 조립/수명 | MainFlow가 CSV, DI, Handler, 입력, Presenter를 생성·연결하고 파괴 시 해제 |
| 외부 경계 | FoundationSave가 저장 형식/검증, SaveLoadHelper가 파일 I/O 담당 |
| 실패 | 범위 초과·잘못된 문자열·파일 누락/손상/버전/I/O 실패는 현재 데이터 유지 |
| 콘텐츠 제외 | 타이틀/캠페인/지도/인물/전투/시간 시뮬레이션 없음 |
