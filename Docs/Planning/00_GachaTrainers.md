# 가챠 트레이너즈 — 핵심 기획

P2에서 개발할 게임은 **가챠 트레이너즈**다. 이 문서는 2026-11-24 사용자가 명시한 게임 방향을 기록하며, 이후 P2의 기획·설계·구현 시 지속적으로 참고하는 기준이다. 후속 사용자 요구로 기획이 바뀌면 이 문서도 함께 갱신한다.

## 사용자 명시 요구

1. 가챠 트레이너즈는 **로그라이크 게임**이며, **매판(런) 초기화**된다.
2. 플레이어는 **가챠 트레이너**가 되어 다양한 종류의 가챠에서 **크리쳐**와 **특성 수정**을 뽑는다. 특성 수정은 **패시브 스킬을 부여**하며, 파티는 **최대 3마리의 크리쳐**로 구성한다. “특성 수정”은 초기 요청의 “특성 결정”과 같은 개념이다.
3. 플레이어는 **실시간 기반의 전투**를 진행한다.
4. 전투 후 **상금 및/또는 유물**을 얻는다. 상금만, 유물만, 또는 둘 다 얻는 경우를 포함하는 표현이다.
5. 다시 2번으로 돌아가 진행한다.

## 씬 구성과 첫 개발 범위 — 사용자 명시 요구

- 전체 씬은 **타이틀 씬 / 가챠샵 씬 / 전투 씬**으로 구성한다.
- 가챠샵에서는 캐릭터를 **WASD로 조작**하여 배치된 가챠 머신과 상호작용한다.
- 머신에 **돈을 지불**하여 새로운 크리쳐 또는 특성 수정을 얻는다.
- 첫 개발 대상은 **타이틀 씬과 가챠샵 씬**이다. 크리쳐 머신 1종과 수정 머신 1종을 배치하며, 크리쳐 3종과 수정 3종의 세부 기획은 구현자가 정한다.

이번 구현의 콘텐츠·가격·조작 등 보완 사양은 [타이틀·가챠샵 기획](02_TitleAndGachaShop.md)에 구분해 기록한다.

## 실시간 전투 추가 요구 — 사용자 명시 요구

- Big Kid Nation의 Pokémon Arena 2D처럼 크리쳐들이 실시간으로 전투하는 전투 씬을 구현한다.
- 테스트 상대는 기본 크리쳐 3종을 사용한다.
- 양측에서 한 마리씩 소환하여 싸우는 방식으로 시작한다.
- 크리쳐가 바라보는 **8방향에 따라 서로 다른 스프라이트**를 표시한다.
- 각 크리쳐의 **대기·이동·회피·피격·스킬 사용 등 동작을 스프라이트 애니메이션**으로 표시한다.
- 아군의 **직접 조작 / 자동 전투를 선택**하고 원하는 때에 출전 크리쳐를 교체할 수 있게 한다.
- 기본 공격은 **마우스 좌클릭**, 스킬은 **우클릭**, 회피는 **Space**로 조작한다.
- 단순 능력치 수정을 **던전 세틀러즈의 각인 효과를 이식한 수정**으로 바꾸고 **희귀도 등급**을 적용한다.
- 기존 크리쳐 3종에 **3종을 추가**한다. 세부 보완 사양은 [크리쳐 3종 추가](05_CreatureExpansion.md)를 따른다.

전투 기본 사양은 [실시간 전투 기획](03_RealTimeBattle.md), 이후 조작 선택·수동 교체·각인 수정과 희귀도 변경은 [조작 선택과 각인 수정](04_ControlAndEngravings.md)에 구분해 기록한다.

## 보유·희귀도·진화 확장 — 2026-11-25 사용자 요구

- 소유 유닛 수를 출전 인원과 별도로 확대한다.
- 직접 조작의 공격 방향은 마우스 방향을 사용한다.
- 크리쳐·수정은 일반/고급/희귀/전설 등급과 50/30/15/5% 확률을 사용한다. 현재 기본 크리쳐 6종은 등급별 3/2/1/0종이다.
- 같은 크리쳐 3마리로 랭크 1→2→3 진화, 매 진화 A/B 선택, 희귀도 유지.
- DS의 각인을 추가하고 최종 전투 능력치를 실제 확인하여 도입한다.
- 2:2 등 전투 확대, 직접 조작 시간/자원 제한 및 5초 개입 스킬은 검토한다.

현재 구현과 임시 선택권 정책, 계통·능력치 수치, 검토 결과는 [보유·선택 진화·전투 능력치](06_CollectionEvolutionAndCombatStats.md)에 구분한다. 이번 확장에서도 매판 초기화와 최대 3마리 출전 파티는 유지한다.

## 스테이지 확장 — 2026-11-25 사용자 요구

- 전체 10개 스테이지, 1스테이지 적 물공·마공·생명력 50% 감소, 다음 단계마다 20% 증가.
- 능력치 배율과 적 구성 배열을 직접 수정 가능한 시트로 관리한다.
- 구현은 매 단계 기본값 대비 +20%p로 해석하며, 배율과 편성은 [스테이지·밸런스 시트](07_StagesAndBalanceSheet.md)를 따른다. 10스테이지 승리 후 모험 완료와 타이틀 복귀를 구현 보완 사양으로 적용한다. 기존 고정 3종 상대는 1스테이지 및 중립 전투 테스트에만 남는다.

## 핵심 반복 흐름

초기 금화·매 전투 보상을 포함한 밸런싱 수치는 코드 상수 대신 CSV에서 조정한다. 경제·확률·크리쳐/스킬·수정·진화·공통 전투의 편집 방법은 [밸런스 시트](08_BalanceTables.md)를 따른다. 기존 문서의 600/100/60/200 G 등은 기본값 기록이며 실행 중 값은 시트가 결정한다.

```text
런 시작
  → 다양한 가챠에서 크리쳐·특성 수정 뽑기 및 최대 3마리 파티 구성
  → 실시간 전투
  → 상금 및/또는 유물 획득
  → 1~9스테이지: 뽑기·파티 구성 단계로 돌아가 다음 스테이지 진행
  → 10스테이지: 모험 완료 후 타이틀

새 런 시작 시 매판 초기화
```

매판 초기화는 런 단위의 규칙이다. 위 반복 흐름의 전투 한 번마다 초기화한다는 의미가 아니다.

## 후속 설계에서 정할 사항

초기 가챠 종류·확률·비용과 수정 적용 규칙은 [타이틀·가챠샵 기획](02_TitleAndGachaShop.md), 초기 전투 조작·상금·패배 시 런 종료는 [실시간 전투 기획](03_RealTimeBattle.md)의 구현 보완 사양으로 정리한다. 현재 최종 승리는 10스테이지 완료다. 유물과 이후 콘텐츠는 아직 정하지 않았다. 이후 구체화할 때 사용자 요구와 구현 시 보완한 사양을 구분해 기록한다.

## 기존 기반 문서와의 관계

[기반 테스트 씬 기획](01_Foundation.md)과 [기반 구조](../Architecture/Foundation.md)는 기존 기반 구현을 설명한다. 초기 기반 구축 요청의 “게임 콘텐츠는 필요하지 않다”는 범위는 당시 테스트 씬에 관한 것이며, 앞으로의 게임 개발 방향은 이 문서를 따른다.
