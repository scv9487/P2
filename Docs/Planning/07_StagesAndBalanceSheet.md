# 10개 스테이지와 밸런스 시트

2026-11-25 후속 요구. 기존 무한 상점↔전투 반복과 고정 테스트 상대를 게임 진행에서 대체한다.

추가된 경제·전투 밸런스 시트는 [게임 밸런스 CSV](08_BalanceTables.md)를 따른다. 스테이지별 금화 보상은 `GachaEconomyTable.csv`의 `Economy.VictoryGold` 배열에서 읽으며, 아래 200 G는 초기 기본값이다.

## 사용자 요구

- 전체 런은 총 10개 스테이지다.
- 1스테이지 적의 물리 공격력·마법 공격력·생명력을 기본값보다 50% 낮춘다. 이후 스테이지마다 20% 높인다.
- 능력치 값 배열과 스테이지별 적 편성 배열을 시트로 관리하여 직접 밸런싱할 수 있게 한다.
- 진행에 따라 적 구성이 달라진다.

## 구현 해석과 기본값

“20% 높게”는 **기본 능력치 대비 매 단계 +20%p**로 해석했다. 이전 단계에 1.2를 곱하는 복리 방식이 아니다. 세 배율은 각각 독립적인 열이며 현재 값 배열은 모두 `[0.5, 0.7, 0.9, 1.1, 1.3, 1.5, 1.7, 1.9, 2.1, 2.3]`다. 런타임 성장 공식으로 다시 계산하지 않고 **각 행의 값을 그대로 적용**하므로 원하는 곡선으로 바꿀 수 있다.

| 스테이지 | 물공 배율 | 마공 배율 | 생명력 배율 | 적 배열: 소환 순서 |
| --- | --- | --- | --- | --- |
| 1 | 0.5 | 0.5 | 0.5 | 잿불여우 → 이끼거북 → 번개토끼 |
| 2 | 0.7 | 0.7 | 0.7 | 이끼거북 → 물결수달 → 서리올빼미 |
| 3 | 0.9 | 0.9 | 0.9 | 번개토끼 → 바위멧돼지 → 잿불여우 |
| 4 | 1.1 | 1.1 | 1.1 | 서리올빼미 → 물결수달 → 번개토끼 |
| 5 | 1.3 | 1.3 | 1.3 | 바위멧돼지 → 이끼거북 → 물결수달 |
| 6 | 1.5 | 1.5 | 1.5 | 잿불여우 → 서리올빼미 → 바위멧돼지 |
| 7 | 1.7 | 1.7 | 1.7 | 물결수달 → 번개토끼 → 이끼거북 |
| 8 | 1.9 | 1.9 | 1.9 | 이끼거북 → 잿불여우 → 서리올빼미 |
| 9 | 2.1 | 2.1 | 2.1 | 번개토끼 → 물결수달 → 바위멧돼지 |
| 10 | 2.3 | 2.3 | 2.3 | 바위멧돼지 → 서리올빼미 → 잿불여우 |

적은 모두 랭크 1, 수정 없는 기본 형태다. 배율은 적의 `PhysicalAttackPower`, `MagicAttackPower`, `MaxHealth`에만 적용한다. 기본 공격의 물리 피해와 스킬의 마법 피해, 최대 생명력 기반 회복 등은 조정된 수치를 소비한다. 공격 속도·이동 속도·저항 등 다른 능력치와 아군은 바꾸지 않는다. 생명력은 정수 반올림(정확히 .5이면 짝수), 최소 1이다. 예: 잿불여우의 기본 생명력 85 × 0.5 → 42.

## 직접 편집하는 파일

**[GachaStageTable.csv](../../Assets/1_InternalTools/Util/DataSheetLoader/Table/GachaStageTable.csv)**를 Excel 또는 텍스트 편집기로 연다. Excel에서는 UTF-8 CSV(쉼표로 분리)로 저장한다. 열 이름을 유지하고 Stage 1~10을 한 행씩 작성한다. 행 순서는 바꿔도 된다.

```csv
Stage,PhysicalAttackMultiplier,MagicAttackMultiplier,HealthMultiplier,EnemyCreatures
1,0.5,0.5,0.5,EmberFox|MossTurtle|VoltRabbit
```

- `Stage`: 스테이지 번호. 1~10을 중복 없이 모두 포함한다.
- `PhysicalAttackMultiplier`: 적 물리 공격력 배율. `1`=100%, `0.5`=50%, `2`=200%.
- `MagicAttackMultiplier`: 적 마법 공격력 배율.
- `HealthMultiplier`: 적 최대 생명력 배율.
- `EnemyCreatures`: **`|`로 구분하는 배열**, 왼쪽부터 한 마리씩 소환. 1~3마리를 설정할 수 있고 같은 종을 여러 번 넣어도 된다. 예: `FrostOwl|FrostOwl`은 올빼미 두 마리다.

| 영문 ID | 크리쳐 |
| --- | --- |
| `EmberFox` | 잿불여우 |
| `MossTurtle` | 이끼거북 |
| `VoltRabbit` | 번개토끼 |
| `FrostOwl` | 서리올빼미 |
| `TideOtter` | 물결수달 |
| `StoneBoar` | 바위멧돼지 |

예를 들어 2스테이지 행을 `2,0.8,0.6,1.2,StoneBoar|TideOtter`로 바꾸면 물공 80%·마공 60%·생명력 120%인 멧돼지와 수달이 차례로 나온다. 앞 스테이지 배율과 무관하다.

Play를 종료하고 CSV 저장·Unity 임포트 후 다시 Play한다. 세 씬의 `GachaMainFlow`에 같은 CSV TextAsset이 직렬화되어 있으며 씬 진입 때 읽는다. 이미 시작한 전투의 복사본은 바뀌지 않는다. 배포한 Player는 빌드에 포함된 CSV를 사용하므로 **변경 후 다시 빌드**한다. 외부 CSV의 런타임 핫리로드는 이번 범위가 아니다.

공격 배율은 0 이상, 생명력 배율은 0 초과여야 한다. 잘못된 헤더·개수·번호·중복·비유한 값·오버플로·알 수 없는 종·빈 편성은 명확한 Console 오류를 표시하고 씬 초기화를 중단한다. 오류를 기본 편성으로 숨기지 않는다.

## 진행과 모험 종료

- 새 런은 스테이지 1, 완료 수 0이다. 상점 도전 버튼과 전투 상단에 현재 스테이지/10을 표시한다.
- 1~9스테이지 승리 확인: 기존 200 G 상금 지급, 완료 수 +1, 같은 보유·파티·수정으로 상점 복귀, 다음 번호에 도전한다.
- 10스테이지 승리: **10개 스테이지 완료 / 모험 성공** 결과를 표시한다. 확인하면 마지막 상금을 한 번 정산하고 타이틀로 돌아간다. 11스테이지는 없다.
- 중복 결과 확인으로 상금이나 완료 수가 추가되지 않는다. 패배·무승부·포기는 기존처럼 런을 끝낸다. 새 모험의 자금·파티·진화·수정·선택권·스테이지를 초기화한다.
- 양측 한 마리씩 실시간 전투·아군 최대 출전 3·자유 교체·직접/자동 조작은 유지한다.

## 검증 범위

`StageProgressionTests`는 실제 CSV의 10단계, 사용자 편집값과 편성 순서·중복·1/2마리 편성, 물리/마법 투사체 소비, 적만 세 능력치 변경, 잘못된 시트 거절, 10회 정산 경계를 확인한다. `StageSceneTests`는 실제 씬/버튼의 1→2 진행과 편성 교체, 10단계 결과→타이틀→새 런 초기화를 확인한다. 결과 화면 테스트의 기절은 fixture로 주입하고, 짧은 편성의 승리는 전투 시뮬레이션으로 검증한다.

2026-11-25 Unity 6000.0.58f2에서 최종 **EditMode 181/181, PlayMode 27/27 통과**. 별도 프로젝트 복사본의 Windows Development Player에서 실제 씬·버튼으로 1~10단계를 순서대로 진행하고 각 단계의 배율·편성·상금, 마지막 완료와 새 런 초기화를 검증했다. Player의 승패 전환은 기절 fixture를 사용했다. 상점·1/2/5/10단계 전투·1/10단계 결과·새 런의 8개 캡처를 남겼고 변경된 UI의 배치와 글자 표시를 확인했다. `105×0.7→74`, `85×2.3→196` 등 생명력 반올림 경계도 회귀 테스트에 포함한다.
