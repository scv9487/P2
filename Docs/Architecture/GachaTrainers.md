# 가챠 트레이너즈 구조와 코드 읽기

## 현재 확장 구조 — 2026-11-25

경제·전투 수치의 현재 원본은 [밸런스 CSV 5개](../Planning/08_BalanceTables.md)다. `GachaBalanceAsset`은 CSV TextAsset 참조만 보유하고 `GachaBalance`가 파싱·스키마/배열/가중치·진화 능력치 검사를 완료한 불변 설정을 만든다. `GachaMainFlow`는 새 런에 이를 전달하고 상점·전투를 오갈 때 같은 런 설정을 유지한다. `PartyCreature`는 구매·장착·진화 시 같은 설정을 계승하며 적도 아군과 같은 설정에 스테이지 배율을 적용한다.

`GachaCatalog`와 `BattleCatalog`의 숫자 정의·확률·설명은 설정에서 구성한다. 기본 생성자/카탈로그 호환 접근도 `Resources/GachaBalance.asset`의 동일한 CSV를 사용하며 별도 숫자 기본값은 없다. 전투의 기본/스킬 피해·각인·기력/쿨다운, 상점 가격표·구매·확률·진화 미리보기, 전투 보상 안내가 해당 런의 설정을 읽는다. `CurrentVictoryGold`는 현재 스테이지의 보상을 조회하며 정산은 단계 증가 전에 이 값을 확정한다. 숫자 설명을 씬에 고정하지 않도록 타이틀/머신 가격 텍스트도 View에 직렬화 연결했다. 기존 스테이지 시트 형식은 유지한다.

밸런스 시트 확장의 최종 검증은 **EditMode 201/201, 실제 씬 PlayMode 29/29 통과**다. 별도 복사본의 CSV를 시작 금화 1234·가격 137/29·단계 보상 17~170 및 다른 전투 수치로 편집한 Windows Player에서도 구매·스킬 피해/소모·10단계 보상·새 런 초기화를 확인했다. 임시 부팅 코드를 제거하고 기본 CSV를 복원한 최종 소스로 두 테스트 전체를 다시 통과했다. 세부 범위와 로그 위치는 [밸런스 시트 검증 기록](../Planning/08_BalanceTables.md#검증-기록)에 있다.

10개 스테이지 확장의 최종 검증은 EditMode 181개 / PlayMode 27개 통과, Windows Player의 1~10단계 전환·CSV 배율/편성·보상·완료/새 런 초기화다. 실제 전투 모델과 결과 fixture를 구분한 범위는 [스테이지 검증 기록](../Planning/07_StagesAndBalanceSheet.md#검증-범위)에 있다. 런타임·씬·시트·테스트 237개 파일의 SHA-256이 검증 복사본과 일치한다. 일회성 Player 부팅·빌드 코드는 실제 Assets에 추가하지 않았으며 QA 복사본에서도 제거했다.

현재 사양은 [보유·진화·최종 전투 능력치](../Planning/06_CollectionEvolutionAndCombatStats.md), [10개 스테이지·밸런스 시트](../Planning/07_StagesAndBalanceSheet.md), [게임 밸런스 CSV](../Planning/08_BalanceTables.md)를 따른다. 아래 과거 검증 기록은 당시 범위의 이력이다.

- `GachaStageTable.csv`는 10개 행의 물공·마공·생명력 배율과 `|` 구분 적 배열을 가진 단일 원본이다. 세 씬의 `GachaMainFlow._stageTable`에 같은 TextAsset을 연결한다. `GachaStageSheet`는 기반 CSV 행 파서를 공유하며 번호·배율·편성 유효성을 검사한 읽기 전용 `StageDefinition` 배열을 제공한다. 누락/잘못된 시트는 오류를 표시하고 초기화를 중단한다.
- `GachaMainFlow.Awake`에서 시트를 읽고 `run.StageNumber`의 정의를 전투 생성자에 전달한다. `CombatStats.WithStageMultipliers`가 적만 세 능력치를 조정한 복사본을 만든다. `BattleFighter`의 실제 최대 생명력·공격·스킬이 이를 소비한다. 시트 없는 기본 전투 생성자는 기존 단위 테스트의 중립(1배) 시뮬레이션 전용이며 실제 씬은 사용하지 않는다.
- `RunDataContainer.ClearedStages`와 `StageNumber`가 진행을 소유한다. 승리 확인 시 한 번 정산하고 1~9는 다음 단계 상점으로, 10은 타이틀로 이동한다. `RunCompleted`이면 새 전투를 거절한다. 상점 도전 버튼·전투 타이머·결과 화면에 단계를 표시하며 전투 결과는 가변 편성 수를 읽는다.

- `RunDataContainer`는 무제한 `Owned` 목록과 최대 3개 `Party` 목록을 별도로 소유한다. 불변 `PartyCreature`는 인스턴스 ID·기본 종·진화 노드·수정을 가진다. 장착 시 보유/출전 양쪽 참조를 함께 교체하며, 선택 인덱스도 같은 개체를 가리킨다.
- `CreatureEvolution`은 기본 6종 × 7개 형태를 정의한다. `TryEvolve`가 동종·동일 노드 3개를 확인한 다음 한 번에 교체하고 수정 재고와 출전 슬롯을 보존한다. A/B 선택 대기 중 재료는 그대로 유지한다. 희귀도는 기본 종에 속한다.
- `GachaCatalog`는 CSV 등급 가중치를 같은 등급의 콘텐츠에 균등 배분하는 정수 추첨 구간을 사용한다. 기본 크리쳐 600개 / 수정 1200개 구간에서 두 가챠의 등급 확률은 50/30/15/5%이며 시트로 변경할 수 있다. 크리쳐 전설 구간은 현재 종이 없어 `LegendaryTokens`로 기록하는 임시 정책이다.
- `CombatStats`는 종·진화 노드·수정에서 22개 최종 전투 능력치를 계산하는 불변 결과다. `BattleFighter`는 이를 참조하고 체력·기력·상태 시간을 소유한다. 기본 공격은 물리, 스킬은 마법, 실제 피해는 DS의 명중/회피→가드/치명타→보너스/저항→보호막 계산을 따른다. 직접 피해 후 흡혈·조건형 각인, 그 뒤 반사를 처리한다. 마격·연소·반사가 각인을 재귀 호출하지 않는다.
- `BattleCombatRequested`는 이동·공격 유지 외에 선택적인 월드 조준점을 전달한다. `GachaMainFlow`의 Input에서 카메라 pixelRect와 UI raycast를 검사해 월드 좌표를 만든다. Handler가 모델에 반영하고 View는 조준점을 읽어 표시한다. 자동 전투는 기존 대상 추적을 사용한다.
- `CollectionSceneView`는 `GachaSceneView`가 Bind/Render/Unbind를 조율하는 직렬화된 하위 View다. 보관함 페이지·수정 선택·진화 선택 버튼은 기존 입력 큐에 요청만 기록한다. 페이지와 모달 상태는 `ShopDataContainer`, 경제·진화 상태는 `RunDataContainer`가 소유한다.
- `EvolutionAdornmentView`는 `BattleActorView`가 읽은 진화 노드·방향·애니메이션 시간으로 실루엣 장식을 표시한다. 기존 1152프레임의 애니메이션과 결합하며 원본 전투 상태를 변경하지 않는다.

실행 순서는 기존과 같은 `Input → EventQueue/Handler → BattleData.Tick → View.Render`다. 중앙 EventQueue 처리 중 재등록이나 View에서 데이터 변경 경로를 추가하지 않았다. DS 프로젝트는 수정하지 않았다.


이 문서는 [타이틀·가챠샵 기획](../Planning/02_TitleAndGachaShop.md), [실시간 전투 기획](../Planning/03_RealTimeBattle.md), [조작 선택·각인 수정](../Planning/04_ControlAndEngravings.md)의 구현 구조를 설명한다. 기존 기반 테스트 씬의 실행 경로는 [Foundation](Foundation.md)에 유지한다.

## 실행 경로

```text
GachaMainFlow.Awake
  씬 종류 확인 → 타이틀이면 기존 런 해제 / 상점이면 현재 런 연결
  ShopDataContainer 생성
  GachaEventHandler에 상태·포커스·추첨·화면 전환 요청 callback 전달
  기존 EventHandler → 기존 EventQueue에 요청 타입 등록
  GachaSceneView.Bind → 버튼 callback은 Submit으로 입력 큐에 기록

GachaMainFlow.Update
  WASD / E / Escape 수집 → 입력 큐
  입력 큐 → EventQueue.AddEvent
  EventQueue.Update → GachaEventHandler.OnEvent
    포커스·현재 씬·모달·거리 검사
    ShopDataContainer / RunDataContainer 변경
  GachaSceneView.Render(IReadOnlyRunData, IShopDataReader)
  보류된 씬 이동이 있으면 큐 처리 종료 후 SceneManager.LoadSceneAsync

GachaMainFlow.OnDestroy
  버튼 구독 해제 / 입력 큐와 EventQueue 대기 요청 제거
```

View는 입력 의도만 기록하고 Reader로 상태를 읽는다. 이동 위치·선택·돈·파티·수정·모달 상태는 DataContainer가 소유한다. 씬 이동은 Handler가 요청을 기록한 뒤 MainFlow가 큐 처리 이후 실행하므로 큐 처리 중 같은 큐에 다시 요청하지 않는다.

전투 씬에서는 같은 MainFlow가 `RunDataContainer.AutoBattle`에 맞춰 `BattleDataContainer`를 생성하고 `BattleSceneView`를 연결한다. 입력 큐 → `EventQueue.Update` → `BattleDataContainer.Tick` → `BattleSceneView.Render` 순서로 실행한다. `BattleCombatRequested`는 WASD 방향·선택적인 마우스 월드 조준점·좌클릭 유지 여부를 전달하며, 별도 UI 기본 공격 버튼은 `TryBasicAttack()`을 한 번 실행한다. 우클릭·Space·Esc·Tab·1/2/3과 UI 버튼은 기존 `GachaActionRequested` 경로를 사용한다. 마우스 위치의 EventSystem raycast가 Selectable 안에 있으면 전투 클릭을 차단한다. 쿨다운이나 자동 모드로 비활성화된 버튼도 클릭을 소비하고, 장식 패널은 아레나 공격을 막지 않는다.

게임 런타임은 기존 `P2.Foundation` 어셈블리에 포함한다. 기존 `Refactor.Main.EventQueue`의 FIFO·처리 중 재등록 금지·Handler 탐색을 재사용하며, `EventHandler`는 게임 Handler를 전달받는 생성자를 추가한다. 게임 Handler는 DI에 등록하지 않고 생성자 인자로 상태와 의존성을 받는다. 기존 기반 Handler의 생성자와 DI 등록 경로는 유지한다.

크리쳐 카탈로그는 6종이며 구매 추첨과 UI는 `GachaCatalog.Creatures`를 사용한다. `BattleCatalog.TestRoster`는 최초 3종으로 고정된 읽기 전용 목록으로, 중립 모델 테스트와 전투 직접 실행 샘플의 아군에서만 사용한다. 실제 적은 직접 실행할 때도 해당 스테이지 CSV 편성을 사용한다. 전체 구매 목록을 테스트 팀이나 파티 한도로 사용하지 않는다. 추가 3종의 수치와 기존 각인 판정과의 관계는 [크리쳐 확장 기획](../Planning/05_CreatureExpansion.md)에 기록한다.

## 상태와 런 경계

- `GachaMainFlow`의 정적 현재 런 참조가 씬 전환 사이의 돈·보유 개체·진화·출전 파티·수정·전설 선택권을 보유한다. 별도의 영구 GameObject는 만들지 않는다.
- `SubsystemRegistration`에서 정적 참조를 비워 Domain Reload가 꺼진 Editor Play 재실행에서도 이전 런을 이어받지 않는다.
- 타이틀 진입은 현재 런을 해제한다. 시작 버튼은 새 `RunDataContainer`를 생성한다. 상점 씬을 직접 실행할 때 현재 런이 없으면 새 런을 만든다.
- `ShopDataContainer`는 상점 씬마다 새로 생성하므로 진입 위치·모달은 초기화한다.
- 새 런은 초기 600 G, 빈 보관함·파티·수정 재고와 선택권 0장으로 시작한다. 게임 런 저장 파일과 자동 불러오기는 없다.
- 포커스 변경·비활성화·파괴 시 보류 입력을 비운다. Handler는 실행 시점에도 포커스와 모달을 다시 확인한다.
- 전투 중에는 `BattleInProgress`가 파티 구매·변경을 잠근다. 승리 결과 확인은 `CompleteBattle(true)`로 한 번만 200 G를 지급하고 완료 수를 늘린다. 1~9단계는 같은 런으로 상점에 돌아가고 10단계는 모험 완료 후 타이틀로 이동한다. 패배·무승부·포기도 현재 런을 해제하고 타이틀로 이동한다.
- 체력은 런 데이터가 아닌 전투 복사본이 소유한다. 전투 도중 교대할 때 생존자의 체력은 유지하며, 새로운 전투에서는 장착 수정이 반영된 최대 체력으로 다시 시작한다.
- 전투 중 포커스를 잃으면 입력을 비우고 전투를 일시정지한다. 포커스 복귀만으로 자동 재개하지 않는다. 재개 요청 이후부터 다시 시뮬레이션한다.

## 구매와 수정 적용

`TryPurchase`는 전투 중 잠금, 머신 종류, 금액, 추첨 결과를 검증한 뒤 한 번만 돈을 차감한다. 출전 파티가 가득 차도 보관함으로 구매할 수 있다. 자금 부족과 잘못된 머신은 추첨 전에 거절한다. 추첨 함수는 Handler에서 주입하며 실제 게임은 `UnityEngine.Random.Range(0, count)`를 사용한다.

`PartyCreature`는 외부에서 변경할 수 없는 값이며 장착·해제 시 식별자·종·진화 노드를 보존한 새 값으로 교체한다. `Owned`, `Party`와 카탈로그는 읽기 전용 컬렉션이다. 수정은 조건형 전투 효과를 부여하며 광대·부싯돌·탄성은 발동을 위한 회피·치명타·가드 확률도 보정한다. 교체·해제·방출·진화 시 수정 재고를 정확히 반환한다. 수정 추첨은 1200개 가중치 구간이며 12종 재고 목록과 6개씩 두 페이지인 구매창을 사용한다. 추가 선정 근거와 DS/P2 수치 차이는 [현재 확장 기획](../Planning/06_CollectionEvolutionAndCombatStats.md)에 기록한다.

상점 위치는 데이터 좌표로 처리하고 View가 Transform에 표시한다. 대각선 입력은 길이를 제한하며 이동 시간 상한과 축별 장애물 검사를 적용한다. 머신 상호작용은 근처 머신 판정과 모달 상태로 제한한다.

## 실시간 전투 시뮬레이션

`BattleDataContainer`는 Unity 씬·Transform·코루틴에 의존하지 않는다. `Tick(deltaTime)`에 들어온 시간을 최대 0.25초로 제한하고 1/120초 고정 간격으로 나누어 이동·AI·재사용 시간·투사체·피해·기절을 처리한다. `IReadOnlyBattleData`와 공개 getter만 가진 `BattleFighter` / `BattleProjectile`로 화면에 상태를 제공한다.

- 출전자는 `Player` / `Enemy` 하나씩이다. 대기 크리쳐는 이동·공격·연소 피해를 처리하지 않고 재사용 시간과 상태 지속 시간만 진행한다. 예외적으로 출전 중 발사한 투사체의 반사는 원래 발사자에게 돌아가므로 벤치에서도 피해를 받는다.
- `Summoning`의 `PhaseTime`은 남은 소환 시간이다. `Fighting`에서만 이동과 공격을 진행한다. 결과 단계에서는 이후 Tick이 시간을 진행하거나 피해를 추가하지 않는다.
- 투사체는 이전 위치부터 새 위치까지 선분으로 충돌을 확인한다. 한 시뮬레이션 간격의 양측 피해를 함께 반영하여 마지막 크리쳐의 동시 전멸을 무승부로 처리한다.
- 기절 후 다음 생존 크리쳐를 선택하고 투사체를 비운다. 양측을 출발 위치에 배치한 뒤 다시 소환 시간을 갖는다. 살아남은 출전자의 체력은 회복시키지 않는다.
- `SetMovement`, `SetBasicAttack`은 유지 입력이며, 실제 키를 놓은 프레임에도 0 / false를 전달한다. `ClearInput`과 일시정지 전환은 남은 입력을 폐기한다.
- AI는 상대와의 거리를 조절하고 횡이동하며 공격·고유 스킬·회피를 선택한다. `ControlMode`는 실제 직접/자동 선택이며 전환 시 유지 입력을 비운다. 자동 모드는 수동 전투 명령을 거절하고 교체·모드·일시정지는 허용한다. Handler가 모드 선택을 런에도 기록하여 다음 전투에 유지한다.
- `TrySwitchPlayer(index)`는 Fighting·비일시정지·다른 생존 슬롯일 때 현재 위치에서 즉시 교체한다. 체력·쿨다운·상대 위치·기존 투사체는 유지하고 이전 이동·동작 입력을 비운다. 교체 자체는 회복·무적·공격 쿨다운 초기화를 제공하지 않는다.
- `BattleProjectile.Source`가 원래 발사자와 수정 효과를 보존한다. 직접 명중 → 실제 피해·각인 → 지연 반사 → 기절 순서로 처리해 반사 재귀를 막고 동시 전멸을 판정한다. 불씨·침몰은 기본 공격 명중 누적, 발악은 발사 시 피해 계산, 사형은 체력 피해 직후 조건을 검사한다. 보호는 실제 출전자 진입에만 적용하며 살아남은 상대의 재배치에는 다시 발동하지 않는다.
- 보호막·연소·패시브 상태는 `BattleFighter`가 소유한다. View는 희귀도·수정 이름·보호막 수치·연소 지속 시간을 표시하고 기존 보호막 Renderer와 몸체 tint로 상태를 표현한다.
- 서리올빼미의 `SlowTime`도 모델이 관리하며 `MovementSpeedMultiplier`는 일반 이동에만 적용한다. 물결수달 회복은 스킬 승인 시 모델이 먼저 처리하고, 바위멧돼지 밀치기는 살아 있는 직접 명중 대상에 진행 방향으로 적용한다. 모두 기존 UI 입력·AI·투사체 경로를 공유하며 View가 게임 상태를 변경하지 않는다.

## 8방향 스프라이트 표시

`BattleFighter.Facing`은 전투 모델이 소유하는 조준 방향이다. `BattleActorView`는 이 값을 `CreatureFacingUtility.FromDirection`에 전달하고, `CreatureFacing`의 동·북동·북·북서·서·남서·남·남동 순서(0~7) 중 가장 가까운 방향을 선택한다. +X가 동쪽, +Y가 북쪽이다. 길이가 0이거나 유효하지 않은 방향은 전달한 기본 방향을 사용한다.

- 양측 `BattleActorView`의 `_animations`는 같은 `CreatureAnimationLibrary` 에셋을 참조한다. 초기 24개 방향 PNG는 `Art/Creatures/`에 유지하고, 실제 전투는 `Art/Creatures/Animations/`의 동작 아틀라스를 사용한다.
- 각 프레임은 256×256 투명 이미지, 공통 피벗 (0.5, 0.375), 128 PPU, 압축·mipmap 없이 가져와 발 위치를 고리에 맞춘다. 각 이미지의 방향별 실루엣·얼굴·등을 사용하므로, 단일 그림을 좌우 반전하던 경로는 사용하지 않는다.
- `_creatureSprite` 하나에 선택한 스프라이트를 연결한다. 몸체의 X·Y 배율은 양수로 유지하고 `flipX`·`flipY`를 끈다. 피격 시 붉은 tint, 회피 투명도, 소환 크기 변화를 동일한 Renderer·몸체 Transform에 적용한다. 이동 자세와 들썩임은 동작 프레임에 포함하며 렌더 프레임 간 위치 차이로 별도 움직임을 추정하지 않는다.
- 그림자·아군/적군 고리·보호막은 별도 Renderer로 유지한다. 전투 불능 크리쳐의 본체와 관련 표시를 숨기며, 교대 시 새 크리쳐의 종류와 방향으로 다시 선택한다.
- View는 `Facing`을 변경하지 않는다. 이동·조준·공격·충돌·피해 계산은 기존 모델 경로를 유지한다.

## 동작 상태와 프레임 재생

`BattleFighter.AnimationState`와 `AnimationTime`은 모델이 소유하고 외부에는 조회만 허용한다. `BattleDataContainer.Step`의 전후 실제 위치로 이동 상태를 갱신하고, 승인된 `BeginBasic` / `BeginSpecial` / `BeginDodge` / `ReceiveDamage`가 각각의 시각 타이머를 시작한다. 재사용 시간을 역산하거나 View에서 액션을 추측하지 않는다.

- `TickTimers`는 동작 시간도 1/120초 시뮬레이션 간격으로 갱신한다. 피격 > 스킬 > 회피 > 공격 > 이동 > 대기 순서로 보이는 상태를 고르고, 가려진 단발 동작의 남은 시간도 진행하여 피격 후 진행 중인 포즈로 복귀한다.
- 대기·이동 시간은 클립 길이로 순환한다. 단발 동작은 남은 시간으로 경과 시간을 계산하고 재발동 시 0초로 돌아간다. `Place`는 교대할 양측 출전자의 동작 시간을 비운다. 일시정지·소환·결과 단계에서 모델이 진행되지 않으므로 재생 시간도 고정된다.
- `BattleActorView.Render`는 방향·동작·시간을 읽고 `CreatureAnimationCatalog.Frame`으로 현재 프레임을 선택한다. 애니메이션 상태를 변경하거나 `Time.time`으로 별도 재생하지 않는다.
- `CreatureAnimations.asset`의 1152개 참조 순서는 `((종 × 6 + 동작) × 8 + 방향) × 4 + 프레임`이다. 36개 `{Kind}_{State}.png` 아틀라스는 1024×2048이며, 각 256px 셀의 4열은 프레임 0~3, 위에서부터 8행은 E·NE·N·NW·W·SW·S·SE다. 프레임 이름은 `{Kind}_{State}_{Direction}_{Frame}`이다. 기존 3종의 첫 576개 참조를 그대로 유지하고 신규 576개를 뒤에 추가했다.
- Unity Importer의 Sprite Rect, GUID와 라이브러리·씬 연결은 메타·에셋·씬에 직렬화되어 있다. 런타임 이미지 생성, Resources 검색 또는 일회성 생성기에 의존하지 않는다.
