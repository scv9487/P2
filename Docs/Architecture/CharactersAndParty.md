# 인물·파티 구조

기획 기준은 [인물과 파티](../Planning/06_CharactersAndParty.md), 수식의 원본 근거는 [DS 전투·성장 이식](CharactersCombatDS.md)이다.

## 상태와 실행 경로

- CharacterSheet/CharacterContent는 불변 인물 정의·성장·전투 설정을 조립한다. 이름·초상화·대사는 기존 TownSheet를 참조한다.
- AdventureProgressDataContainer는 인물별 친밀도, 레벨, 경험치, 6종 능력치의 누적 성장량, 활성 파티 순서와 인물별 금화를 소유한다. CharacterProgress/MajorStats/CharacterGrowthState는 조회 가능한 불변 값이다. 현재 주요 능력치는 현재 CharacterDefinition.BaseStats + 저장된 GrowthStats이며, 파생 CombatStats까지 시트로 재계산한다. 최종 전투 수치를 저장하지 않는다.
- CharacterInteractionData는 선택 대상·방문자/동료 구분·대화 표시·입력 문맥만 소유한다. 영속 변경은 하지 않는다.
- 공통 상호작용은 UIInputStream → InputBinding → CharacterActionRequested → CharacterEventHandler → MainFlow 조율 → AdventureProgressStore로 흐른다. 기존 마을 방문자 요청도 유효한 장소·인물 검사를 통과한 뒤 같은 상세를 연다.
- UI는 Reader로 표시하고 의도만 기록한다. 이전 팝업/같은 프레임 중복 요청은 문맥 ID와 데이터 Revision으로 거절한다. 영입 실패 후에도 새 문맥을 발급한다. 저장 실패 재시도에서는 영입 난수를 유지한다.
- 상세가 열렸을 때 Town/Dungeon Handler는 뒤쪽 요청을 차단한다. Esc는 현재 상세만 닫는다. MainFlow는 상세 중 CombatTickFlow를 진행시키지 않는다.

## 던전 연결

- DungeonDataContainer는 기존 임시 두 명 대신 진행 저장의 활성 파티로 CombatantData를 만든다. 플레이어만 수동 행동하고 동료는 TickFlow에서 자동 공격한다.
- 마을/던전 방문자 목록과 실행 시점 판정 모두 활성 파티를 제외한다. 추방·영입 성공 후 던전 아군 목록과 화면을 함께 갱신한다.
- 탐험 중 모든 참가자의 CombatantData를 보관하여 추방·재영입을 통한 체력 초기화를 막는다. 파티에서 빠져도 원래 참가 기록은 정산에 사용한다.
- DS 기본 공격의 전체 지연 / 공격 속도를 게이지 주기로 변환한다. CombatCalculator가 원본 판정·피해·흡혈을 계산하며 DungeonDataContainer가 결과를 적용한다.
- 처치 경험치는 별도 사실 큐에 기록한다. MainFlow가 EventQueue 처리 뒤와 TickFlow 뒤에 보상을 저장하고 캐릭터 성장 및 파생 전투 수치를 동기화한다. 중앙 EventQueue에 재등록하거나 View에서 변경하지 않는다. 동료 처치 직후 TickFlow는 후속 성장 적용을 위해 반환한다.
- 경험치 저장 실패 시 진행을 멈추고 재시도 팝업을 표시한다. Store는 같은 보상 ID의 성장 후보를 유지하여 재시도 중 재추첨을 막는다.
- 기존 생성자의 인물 인자가 없는 경로는 기반 회귀 테스트용 임시 파티를 유지한다. 실제 마을/던전 MainFlow는 항상 CharacterSheet와 진행 데이터를 연결한다.

## 저장

아래 v3 원천 데이터는 [의뢰 추가 후 v4 저장](Quests.md)에서도 보존된다.

- Adventure 저장 v3는 기존 v1/v2 금화·소지품·정산·상인 재고·거래 기록에 인물 원천 배열, PartyIds, CharacterActionIds를 추가한다.
- v1/v2는 기존 자산을 보존하고 7명 원천 상태와 플레이어 단독 파티를 메모리에서 초기화한다. 읽기만으로 파일을 덮어쓰지 않는다. 다음 성공한 변경 저장에서 v3로 이행한다.
- 파티는 플레이어가 첫 번째이며 중복 없이 최대 4명이다. 인물 ID/평행 배열 길이/레벨/경험치/친밀도/능력치 범위를 검증한다. 손상이나 지원하지 않는 버전은 원본을 보존하며 변경을 차단한다.
- v3의 `CharacterStrengthGrowth` 등 여섯 배열은 초기 0인 누적 성장량이다. DS의 초기 생성 난수는 아직 없으므로 생성 보정은 0이고, 현재 기본값 + 성장 보정의 순서로 복원한다. 기본값이나 전투 계수 시트가 바뀌어도 성장 보정은 그대로 남으며 새 최종값을 계산한다.
- CharacterSheet를 생략한 이전 기반/상점 전용 경로는 원천 성장량을 그대로 보존한다. 이때 기준 시트가 없는 최종 Stats/Growth 조회는 명시적으로 거절하며, 실제 게임 MainFlow는 항상 CharacterSheet를 연결한다.
- 경험치 저장값은 유한한 비음수 범위를 검사한 뒤, 시트가 있으면 현재 레벨의 경험치 상한으로 제한하여 복원한다. 경험치표 하향 조정을 저장 손상으로 처리하지 않는다. 복원 중에는 성장·쓰기 없이 상한 상태를 유지하고 다음 경험치 지급에서 자동 성장한다.
- 대화·영입·추방·성장·거래·정산은 같은 진행 데이터의 복사본을 저장한 뒤 원본을 교체한다. 다른 기능의 저장이 인물/파티나 재고를 초기화하지 않도록 함께 복사한다.

## 검증

- Unity 6000.0.58f2에서 최종 EditMode **198/198**, PlayMode **17/17** 통과. 결과는 `Logs/Characters-Final-EditMode.xml`, `Logs/Characters-Final-PlayMode.xml`에 있다.
- EditMode는 DS 수식·판정 순서·성장 범위, 0/100 친밀도의 영입 경계, 파티 정원·추방, 이전 저장 이행·손상 보존·실패 재시도, 기본값/경험치표 변경 후 복원, 소수 기본값에서 정확한 성장 증가분 저장을 포함한다.
- PlayMode는 실제 타이틀·마을·던전 씬의 입력과 연결을 실행한다. 방문자 중복 제외, 하단 파티와 상세, 전투 중 상세에 의한 일시 정지, 동료 자동 행동, 거래·정산 회귀 및 지도 안내문이 파티 바에 가려지지 않는 배치를 검사한다.
- Windows Development Player 빌드 성공. 별도 저장 경로의 검증 코드로 EventSystem의 최상단 Raycast 대상에 포인터 이벤트를 전달하여 대화·영입·추방·정원·던전 진입·전투 입력을 실행했다. 프로세스를 다시 시작해 관계/파티 저장과 처치 성장 저장을 각각 복원하는 네 가지 시나리오가 모두 성공했다.
- 전투 시나리오는 검증용 4인 파티에 29 EXP를 부여한 뒤 실제 회색쥐 1마리 처치로 각자 2 EXP를 얻어 레벨 2가 되는 흐름을 확인했다. 여섯 증가분이 각각 2~4인지, 현재HP가 회복되지 않는지, 저장된 성장 원천과 재시작 후 최종 능력치가 같은지 검사했다. 일반 새 게임의 기본 능력치에는 이 검증 시드를 적용하지 않는다.
- `Logs/CharacterPlayerQA/`에 결과 네 파일과 1280×800/1024×768 캡처를 보관했다. 주점 6명, 상세, 마을·던전의 4인 카드, 전투 및 성장 상세의 배치를 확인했다. 실제 사용자 저장은 사용하지 않았으며 일회성 검증 부팅 코드와 임시 빌드는 제거했다.
