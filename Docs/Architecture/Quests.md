# 의뢰 구조

기획 기준은 [길드 의뢰](../Planning/07_Quests.md)다. 기존 인물·상점·전리품과 같은 Adventure 진행 저장을 사용한다.

## 입력과 상태

- QuestContent/QuestSheet는 의뢰 정의와 구조 노드, 문구를 읽고 던전·아이템·연결 지점 참조를 검사한다. DungeonContent가 시트 에셋을 연결한다.
- TownDataContainer.QuestBoardOpen은 장소 모달 상태다. QuestBoardData는 선택 카드와 입력 문맥만 소유하며 영속 의뢰 진행을 바꾸지 않는다.
- View → UIInputStream → QuestActionRequested → QuestEventHandler → MainFlow → AdventureProgressStore 순서로 수락과 보고를 처리한다. 같은 중앙 EventQueue에 새 요청을 재등록하지 않는다.
- MainFlow는 활성 모달·문맥 ID·선택 의뢰·진행 Revision을 검사한다. 닫힌 창이나 이전 선택의 지연 요청, 중복 보고와 뒤쪽 장소/인물 입력을 거절한다.
- QuestRules는 현재 진행과 소지품으로 카드 상태·목표 수량·수주/보고 가능 여부를 계산한다. UI와 저장 처리에서 같은 기준을 사용한다.

## 던전 사건

- DungeonDataContainer 생성 때 활성 의뢰의 수락 ID를 확인하고 필요한 구조 노드만 이번 탐험의 지도에 추가한다. 원본 DungeonSheet의 노드·연결 목록을 변경하지 않는다.
- 적 사망과 구조/최종 보스 승리 지점에서 사건을 FIFO에 기록한다. 사건에는 고유 ID, 수락 ID, 종류, 대상 던전/층/적과 수량을 담는다.
- MainFlow.CommitDungeonProgress는 중앙 입력 처리 뒤와 CombatTickFlow 뒤에 경험치와 의뢰 사건을 저장한다. 저장한 사건만 큐에서 제거하며, 저장 실패는 기존 ProgressSaveBlocked와 상세 닫기의 재시도 경로를 사용한다.
- 처치와 파티 카드 선택이 한 입력 배치에 함께 들어오면 미저장 경험치/의뢰 사건이 있는 동안 인물 상세 열기를 거절한다. 저장 전 Revision으로 상세가 열려 대화·추방이나 성장 저장 재시도가 무효화되는 일을 막는다.
- 의뢰 수락 전에 발생한 사건, 다른 수락 ID의 사건, 다른 대상 사건과 이미 처리한 사건은 목표를 올리지 않는다. 처치는 필요한 수량까지만 누적한다.

## 저장

- Adventure v4에 활성 의뢰·수락 ID·진척·완료 의뢰·처리 기록을 추가한다. 기존 v1~v3를 읽을 때 기존 금화·아이템·상인·인물·파티를 보존하고 의뢰가 없는 상태로 시작한다. 읽기만으로 파일을 덮어쓰지 않는다.
- 변경 후보를 복사해 저장한 뒤 현재 상태로 교체한다. 아이템 납부의 차감, 보상 금화, 완료 기록은 하나의 저장에 포함한다.
- 상점·정산·인물·성장 등의 기존 저장 작업도 의뢰 상태를 보존한다. 손상·지원하지 않는 저장은 원본을 보존하고 변경을 차단한다.

## 검증

- Unity 6000.0.58f2에서 EditMode **250/250** 통과(`Logs/Quests-EditMode.xml`). 기존 198개에 의뢰 데이터·저장 43개와 던전 통합 9개를 추가했다. 수락 시점, 대상 필터, 중복 방지, 시트 변경, v1~v3 이행, 선택적 시트 없는 보존, 납부·보상 원자성과 저장 실패 재시도를 검사한다.
- PlayMode 최종 **21/21** 통과(`Logs/Quests-Final-PlayMode.xml`). 새 의뢰 씬 검사 4개는 네 카드/배경 차단/낡은 입력, 단일 활성 의뢰와 재로드, 납부·보고의 실패/중복 처리, 구조 전투의 저장 실패 차단·복구·재방문·보고, 손상 저장 보존을 포함한다. 기존 길드 검사는 설명 팝업에서 실제 의뢰 게시판으로 변경된 흐름에 맞췄다.
- Windows Development Player 빌드 성공(`Logs/Quests-Build.log`). 격리된 v3 시드 저장에서 실제 UI 경로로 회색쥐 처치 수주·전투 → 정산에서 꼬리 3개 구매 → 처치 보고 → 꼬리 납부 → 구조 노드 전투·재방문 → 구조 보고 → 3층 최종 보스 공략·보고를 실행했다. 네 의뢰 완료, v4 이행, 정확한 아이템 차감과 각 보고 보상의 1회 지급을 확인했다.
- 새 프로세스에서 완료 네 건·보유 금화·동료 금화·파티·소지품을 복원하는 검사도 성공했다. `Logs/QuestPlayerQA/result.txt`, `reload-result.txt`와 두 Player 로그에 결과를 남겼다. 실제 사용자 저장에는 접근하지 않았다.
- Player 검증은 EventSystem 최상단 raycast 대상에 합성 포인터 입력을 전달했다. 검증용 높은 능력치의 2인 파티와 4배속을 사용해 전투·의뢰 연결을 확인했으며 기본 난이도 밸런스 평가와는 구분한다. 1280×800 및 1024×768에서 게시판, 납부, 구조 지도·구출 결과, 완료 후 재시작 화면을 확인했고 PNG 15장을 `Logs/QuestPlayerQA/`에 보관했다.
- 임시 Player 부팅/빌드 코드와 외부 검증 빌드는 제거하고 실제 콘텐츠, 시트, 기능 코드와 회귀 테스트만 유지한다.
